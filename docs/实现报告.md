# 手势音游 实现报告

- **项目**：手势音游 / Gesture Rhythm（双手手势下落式音乐游戏）
- **日期**：2026-11-16
- **运行环境**：Windows 11 / Python 3.12.4 / pygame 2.6.1 / OpenCV 4.10.0 / MediaPipe 0.10.21

本文说明游戏的规则、实现结构与验证结果。运行方式见 [README](../README.md)。

## 一、玩法与规则

### 1.1 状态机

```
READY --(双手张开保持 0.7 s)--> PLAYING --(机会用尽)--> OVER
  ^                                                       |
  +------------------(点击「重新开始」/ 空格)--------------+
```

- **READY**：显示标题、张开双手示意图、张开进度、历史最高分；双手（每只手至少 3 根长指伸出）
  保持 0.7 s 后开始。松手时进度快速回落，不会误触。
- **PLAYING**：每帧比对双手识别结果与屏幕上的音符。
- **OVER**：显示本局得分、历史最高分、命中/最高连击/漏掉次数；「重新开始」只回到 READY，
  下一局同样要重新双手张开（保证每局开始都有同一个动作门槛）。

### 1.2 手势编码

一只手 6 个字符：`[P|N] + 拇指、食指、中指、无名指、小指（1 展开 / 0 收起）`。
两只手共 12 个字符，顺序是**画面左边的手 + 画面右边的手**。

拇指朝向按画面位置定义：

- 画面**左边**的手：拇指朝**右** → `P`，朝左 → `N`；
- 画面**右边**的手：拇指朝**左** → `P`，朝右 → `N`。

即 `P` 指向屏幕中央、`N` 指向外侧。

### 1.3 四档手势（共 196 个）

| 分值 | 颜色 | 规则 | 数量 |
| --- | --- | --- | --- |
| 5 | 绿 `(72,219,130)` | 两手手型相同且在 `{11111, 00000}`；`11111` 可 P/N，`00000` 只能 P | 4 + 1 = **5** |
| 10 | 蓝 `(82,168,255)` | 两手手型相同且在 `{01000, 01100, 01110, 01111, 00111}`；拇指都是收起的，只能 P | 5 × 1 = **5** |
| 15 | 黄 `(250,200,70)` | 两手手型相同且在 `{10000, 11000, 11100}`；拇指都是伸出的，P/N 任意 | 3 × 4 = **12** |
| 20 | 红 `(255,88,102)` | 两手手型**不同**，各自取自上述全部 10 种手型；N 手按拇指规则 | **174** |

**N 手拇指规则**：`N` 手（拇指朝外）必须伸出大拇指，`P` 手不受限（伸、屈都可以）。
朝外又收起的拇指在画面里很难辨认，因此不作为音符要求。20 分的推导：10 种手型的有序不同对共
90 对；拇指位为 1 的 4 种（`11111`、`10000`、`11000`、`11100`）每只手有 2 种选择，
其余 6 种只有 `P` 一种，`4×3 对 ×4 + 4×6×2 对 ×2 + 6×5 对 ×1 = 48 + 96 + 30 = 174`。

不是音符的编码（例如手型 `10101`、`N00000P00000`）仍然能识别并显示，但不与任何音符匹配、不扣分。

### 1.4 对局规则

| 事件 | 处理 |
| --- | --- |
| 命中 | 当前 12 字符编码与音符完全相同 → 消除**最靠下**的匹配音符、加分、连击 +1、0.22 s 冷却 |
| 漏掉 | 音符顶端越过判定线 `y = 700` → 扣 1 次机会、连击清零、0.5 s 红屏 |
| 结束 | 机会归 0 → 写最高分（`highscore.json`）、显示结束界面 |
| 重开 | 点击按钮 / 空格 / 回车 → 回到 READY（不直接开始） |

整局 3 次机会，得分是消除音符分值之和，历史最高分单独持久化。

### 1.5 难度曲线

难度在 90 秒内分三段推进（默认 `RAMP_SECONDS = 90`，阶段边界按 1/3、2/3 划分）：

| 阶段 | 时间 | 变化的参数 |
| --- | --- | --- |
| ① 音符种类 | 0–30 s | 只有音符种类在变：`w10 = 0.35·t`、`w15 = 0.30·t^1.5`、`w20 = 0`（t 为本段进度），到 30 s 时 5/10/15/20 权重为 0.35 / 0.35 / 0.30 / 0；间隔 1.90 s、速度 105 px/s 不变 |
| ② 间隔 + 速度 | 30–60 s | 生成间隔 1.90 → 1.10 s、基准速度 105 → 175 px/s 同步线性加快；音符权重保持不变；仍无红色音符 |
| ③ 红色 + 极限 | 60–90 s | 红色权重 0 → 0.25，5/10/15 同步变为 0.20 / 0.30 / 0.25；间隔 1.10 → 0.55 s、速度 175 → 290 px/s 推到极限 |

- 第二阶段刻意不到极限（1.10 s / 175 px/s），最后 30 秒才把三个参数一起推到终点。
- 单个音符的速度为 `基准 × (1 + 0.55·u^k)`，k 随速度提升从 1.0 降到 0.35：同一时刻落下的音符速度不同。
- 基准速度本身在 30 s 后叠加缓慢波动（幅度随速度爬升到 ±9%），所以下落速度既有音符间的差异，
  也有时间上的起伏。
- 开局只有绿色 5 分音符，红色 20 分只在 60 s 之后出现。

## 二、实现结构

| 模块 | 职责 |
| --- | --- |
| `gesture_rhythm.py` | 主程序：pygame 三个界面、摄像头窗口叠加、主循环、窗口缩放、键鼠输入 |
| `gesture_twohands.py` | MediaPipe 双手识别：整帧输入、左右手排序、关节角判定、平滑、骨骼绘制、后台采集线程 |
| `gesture_catalog.py` | 12 字符编码 / 解码、196 个音符手势的分类表与随机取音符 |
| `gesture_icons.py` | 程序化绘制手势图、音符卡片、当前手势面板 |
| `game_core.py` | 纯游戏逻辑：音符、难度、生成器、命中、机会、状态机、最高分 JSON |
| `sound_effects.py` | numpy 合成音效，按事件类型播放，无音频设备时自动关闭 |
| `camera_compat.py` | 摄像头探测（DirectShow / MSMF / AUTO）与虚拟摄像头回退 |
| `capture_screens.py` | 无头运行真实游戏循环并截图到 `docs/`（同时充当集成冒烟测试） |
| `test_rhythm_logic.py` | 单元测试（无摄像头、无窗口、无音频） |
| `verify_environment.py` | 环境自检（依赖、文件、手势表、识别管线、摄像头、pygame、游戏逻辑） |

数据流：摄像头线程读帧 → 镜像 → MediaPipe → 单手 6 字符（平滑）→ `GestureFrame`
→ 主线程 `RhythmGame.update()` → 场景绘制 → `imshow` 预览。

游戏窗口按 480×800 设计，实际按 87.5% 等比缩小显示为 420×700；鼠标坐标在窗口坐标与场景坐标间换算。

## 三、双手识别

1. 画面先做自拍镜像 `cv2.flip(frame, 1)`，再**整帧**送入 MediaPipe Hands
   （`max_num_hands=2`，`model_complexity` 默认 0，可用 `GAME_HAND_MODEL=1` 换更精确但更慢的模型）。
2. 双手按 landmark 平均横坐标排序，**左边的手记为 L、右边记为 R**（不依赖 MediaPipe 的
   handedness：镜像画面下它与实际左右相反，而玩家看到的是画面位置）。
3. 所有几何在 **3D** 上计算（MediaPipe 的 z 与 x 同量级），手指指向摄像头时不会因 2D 投影
   变短而误判。
4. 长指只看**关节夹角**：PIP（MCP-PIP-DIP）≥ 158° 且 DIP（PIP-DIP-TIP）≥ 140° 才算伸直；
   勾指、半握（150°）都判为收起。
5. 拇指：折叠是绕拇指根部旋转，拇指自身关节链基本保持伸直，因此用
   `IP ≥ 150°` 且 `指尖离掌心 ≥ 0.72 × 掌宽` 判断；握拳时拇指搭在手指上（约 0.4–0.65 倍掌宽）
   不会被误判为伸出。
6. 拇指朝向：先看拇指尖相对掌心的横向位移（`|dx| ≥ 0.22 × 掌宽`），拇指接近竖直时退化为
   「拇指根部相对食指根部」的横向位置。
7. 稳定性：每只手保留最近 4 帧的 6 字符，逐字符多数表决（严格过半，否则沿用上一结果）。
   左右手按位置分别维护历史，手消失时清空。
8. 摄像头窗口：两只手用不同颜色绘制 21 点 + 连边，手腕旁标注 `LEFT/RIGHT + 编码`；
   左上角 RECOGNITION 面板逐行显示 LEFT / RIGHT 的 6 字符编码、拇指 `EXT/FOLD` 和合并后的
   12 字符编码，缺手显示 `not detected`；底部显示游戏状态与张开进度。
9. 采集 + 识别在 `CameraWorker` 后台线程中运行，主线程每帧只取最新结果，游戏逻辑稳定 60 fps。

## 四、界面

| 界面 | 内容 |
| --- | --- |
| 开始 | 标题「手势音游 / GESTURE RHYTHM」、张开双手示意图、张开进度条、历史最高、三条玩法说明；摄像头不可用时显示橙色提示 |
| 游戏中 | 顶部 HUD（得分、历史最高、3 个心形机会、难度等级与进度条、连击）；3 条轨道 + 判定线 + 发光底边；底部「当前手势」面板（实时双手图、12 字符编码、可消除的分值与数量） |
| 结束 | 半透明遮罩 + 面板：游戏结束、本局得分、历史最高、命中/最高连击/漏掉（或「新纪录！」）、「重新开始」按钮（鼠标悬停高亮） |

- **音符卡片** 140×130：双手手势图 + 分值，5/10/15/20 分分别用绿/蓝/黄/红。
- **手势图**：`gesture_icons.py` 用掌 + 5 指程序化绘制，展开的手指画长、收起的画短，
  拇指按 P/N 画在左/右侧。**收起的大拇指画成短杆，并用虚线勾出伸出时的大拇指轮廓**，
  提示这只手的拇指保持收起，避免与伸出的大拇指混淆。手形按 `(编码, 左右手, 颜色, 尺寸)` 缓存，
  卡片再按 `(编码, 分值, 尺寸, 字体)` 缓存。
- **反馈**：命中飘 `+5/+10/+15` 与彩色边框闪光，漏掉红屏，连击 ≥ 2 显示连击数。
- **音效**：5/10/15/20 分命中音高不同，另有漏掉低音、开始上行、结束下行；`GAME_NO_SOUND=1` 可关。

## 六、已知限制

1. 摄像头窗口的实时路径在开发机上没有真实摄像头，只能用虚拟摄像头验证；实际手感需要在有摄像头的
   机器上按 `check_camera.bat` 后实测。
2. 拇指朝向在「拇指笔直朝上/朝下」时本质上有歧义，代码用拇指根部侧向做兜底，可能偶发 P/N 抖动；
   摄像头窗口会实时显示 12 字符，便于自查。
3. 20 分档 174 种手势，玩家不可能记全，只能看卡片图片；双手交叉时左右手会按画面位置交换。
4. 摄像头分辨率与手在画面中的大小会影响 landmark 精度：手离镜头越近、占比越大越准。
5. 游戏需要摄像头才能开始（开始必须双手张开），虚拟摄像头只用于打开界面/截图。
6. 没有暂停功能；退出用 ESC。
